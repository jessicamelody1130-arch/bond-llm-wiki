# Workflow 反思（以 2026-11-14 實際檢查為依據）

## 1. 哪個節點容易出錯？

目前有兩類確實觀察到的失敗／缺漏：

- **Gate B 的來源對照：** 在 Wiki 的 `bond-yields` 主題中，Current Yield 的敘述原本引用 SRC-003，但該文件沒有直接、明確的 Current Yield 定義。此問題是在核對原文時發現的，並非虛構測試。
- **Gate C 的鍵盤互動：** 初版 HTML 按鈕被點擊後取得焦點，此時箭頭鍵因事件處理器排除所有 `BUTTON` 元素而無法繼續切頁；在 Node.js DOM 模擬中的 `keyboard_when_button_focused` 首次測試失敗。

目前未對全部節點執行足夠多次完整運作，因此**不能以失敗次數統計斷言某一節點「最常」出錯**。就已發現的內容品質問題而言，來源對照是最需要前移檢查的節點。

## 2. 我把檢查往前移到哪裡？

初版是先建立 Wiki 概念頁，才檢查引用。修正後將**每個重要定義能否在原始資料中定位**列入 Gate A 後、寫入 Wiki 概念頁之前的檢查；缺少明確來源時先補來源，而不是先放入簡報再處理。

對 HTML 則將「按鈕取得焦點後仍能使用方向鍵」加入 Gate C 的回歸測試，而不是只檢查 JS 語法及頁面數。

## 3. Workflow／Graph 修改內容

**原流程：** 取得來源 → Ingest → 建立 Wiki → 查詢 → 生成簡報 → 檢查。

**調整後：** 取得來源 → Ingest → **來源覆蓋／術語定義檢查** → Wiki → 檢索 → **來源對照與金融數值驗證** → HTML → **DOM 互動模擬及待執行的真實瀏覽器測試** → 紀錄。

- 來源未過：回到資料查找及 ingest，確認對應 source ID 可定位原文。
- 金融概念未過：回到 Wiki 概念頁，補足來源或重新驗算。
- HTML 未過：修改受影響的腳本，再執行 Gate C 回歸測試。
- 每類相同錯誤最多自動重試兩次；無法通過時標示未完成、不宣稱成功。

## 5. 限制及後續驗證

目前來源紀錄為**8 篇公開網頁的結構化來源卡／摘要**，不是 8 篇原始全文的離線快照。部分來源有登入限制，特別是 CFA Institute 的完整教材。正式繳交前仍需打開 GitHub Pages 網址做真實瀏覽器操作測試，並視老師對 ingest 的定義補上可檢索的合法原文或具可重現來源定位的更完整資料。

## 2026-11-14 補強 Gate A：可重跑的筆記 Ingest

舊版只有來源卡與人工摘要，缺乏可重跑的逐篇輸入與 checksum。補建 `raw/curated/` 六份自行改寫的結構化來源筆記、`scripts/ingest_curated.py` 與每篇輸入 SHA-256。

**第一次重跑觀察到兩類錯誤**：
1. SRC-003、SRC-005、SRC-006 的 `source_section` 與 manifest 章節清單不相符；修正後綁定至已核對的原始網頁章節。
2. SRC-003 的其中一則筆記字數低於預設閾值，重新補齊風險敘述後通過。

**結果**：6/6 份結構化筆記匯入成功、12 條 claim 完成來源章節映射。`full_original_text_ingest_count = 0`，不能宣稱已完整抓取 6 篇正文。新的 Gate A 改為「輸入來源筆記 → 章節清單比對 → 筆記品質檢查 → 產出 claim map → 才整合 Wiki」，把錯誤攔在後續簡報生成之前。

## 2026-11-14 Stage 7：簡報深層連結的回歸測試

新增測試時發現，簡報導覽原本透過 `history.replaceState` 更新 `#1` 至 `#10`，但當讀者點擊頁首「返回首頁」連結，或手動輸入含片段識別碼的網址時，並未監聽 `hashchange`，因此頁碼與畫面可能不同步。此次將 `hashchange` 事件加入 `slides/script.js`，讓頁碼連結與可見投影片一致，再加入「返回首頁」及「片段連結導航」兩項回歸案例。Node.js DOM 模擬 **14/14 通過**。

另以新建的 `scripts/test_site_predeploy.py` 獨立驗證本地網站連結與頁內錨點、10 頁 Wiki 來源映射、來源卡、債券價格及 Duration 重新計算，共 **35/35 通過**。此為靜態與模擬測試；Chromium 嘗試仍逾時，**不構成真實瀏覽器驗證成功**。

正式發布前應在一般瀏覽器檢查頁首返回首頁、網址 `#3` 直接跳頁、前後切頁、鍵盤、圖表、測驗，並以真實結果更新 Gate C 紀錄。

## Stage 8：阻止把測試資料當成原始資料（實際測試）

**風險**：新的本地匯入器若只檢查文字量及段落數，之前的合成 HTML 測試頁也可能被誤算為外部來源完成 ingest。

**檢查前移**：在執行原始來源解析之前，加入已知 fixture 檔案 SHA-256 比對；吻合時立即失敗，而不進行計數或寫入正式原文存檔。

**實際測試**：6 個合成網頁檔全部被拒絕，正式原文 ingest 成功數維持 0；詳見 `logs/runs/ingest-saved-html-fixture-rejection.json`。此結果避免錯誤提高完成度，但實際外部來源仍必須在可連網環境補入。


## Stage 9 — Browser execution versus URL navigation
本環境以 Chromium 開啟 `file://` 和 `localhost` 均受管理政策封鎖；改成將簡報 HTML/CSS/JS 注入 Chromium 真實頁面，完成 19/19 DOM 互動測試。這是測試執行方式改良，而非已完成網站部署。未發布網址之 HTTP 載入與跨頁連結驗證仍應在 GitHub Pages 啟用後執行。
